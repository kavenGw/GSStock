## L1 Phase A 放行看 evidence mtime 稳定，不看 report 是否存在

**规则**：report 是一次性产物、evidence 是累积产物——校准轮只追加 evidence 不重写 report，
所以「report 已存在」对「这一路是否真的收工」没有判别力。收工判据是 evidence 文件 mtime
连续数分钟不变 + 比对行数。**别在任何一路仍可能被追加时放行 Phase B。**

**机制**：`python scripts/deep_redo_gate.py <股票名> <日期> --phase A --quiet-min 3`

**案例**：

**Phase A 的放行闸门要看 evidence 的 mtime 稳定性，不是 report 是否存在**：光智轮 A1 背了三轮跨路校准，
它在 12:00 就写了 report 并自述收工，控制者据此在 12:09 放行 Phase B——但 A1 随后又追加了「附录 A：逐条裁定」
共 325 行，**12:14 才落盘，晚于 Phase B 派发 5 分钟**。附录里有 10 条会改写正文的硬事实（未弥补亏损超实收股本
2 倍、直接材料占营业成本 54.32%、第一大供应商即关联方占采购 28.23%、走私罚金未计提且全年公告零披露……），
并且**纠正了控制者内联给写手的一处事实错误**（护盘"三件套"里的"回购"根本不存在，全年 79 条公告无回购）。
只能靠控制者在 12:20 追发补正、Phase B 在途回改来补救。
**根因**：report 是一次性产物，evidence 是累积产物——**校准轮只追加 evidence，不会重写 report**，
所以"report 已存在"对"这一路是否真的收工"没有判别力（与「善后自报不可信」同源）。
**修法**：对背了校准的路，收工判据改为「evidence 文件 mtime 连续数分钟不变」+ 比对行数，
或在校准指令里明写「补充写完后重写 report 的 `end:` 时间戳」。**别在任何一路仍可能被追加时放行 Phase B。**

## L2 校准消息在途 ≠ 已闭合；要么发完等回复，要么主动接受重叠

**规则**：subagent 的「收工」信号只对它当时手上的任务有效，对控制者刚发出、它尚未读到的校准项无效。
放行前若发现两路结论有冲突，主动开一轮对质并等其收敛再放行，而不是放行后边写边转；确需在途转发时须明确
标注「此为未定稿的跨路结论」。

**机制**：仅措辞

**案例**：

**发出跨路校准后，不能只凭「它说收工了」就过汇合闸门**：光迅轮 A1 于 08:48 报「第一轮收工」，控制者逐份亲验文件后于 08:53 放行 Phase B——但控制者 08:50 前发出的**校准消息仍在 A1 队列里未被读到**，它随后又跑了第二轮（13min），产出两条**改变正文写法**的硬发现（存货增量的原材料拆解、定增曾降价 19% 才发满下限）。结果是 Phase A/B **非预期重叠**，违反「阶段严格串行」。本轮成本可控（增量是**在途推送**而非成稿返修），但根因是闸门判据错了：**subagent 的「收工」信号只对它当时手上的任务有效，对控制者刚发出、它尚未读到的校准项无效**。正确做法二选一：**校准要么在放行前发完并等它明确回复「校准项已闭合」，要么就主动接受重叠、并准备好在途推送**——最坏的是以为串行、实际重叠。

stock-deep-redo 放行 Phase B 后，Phase A 的 A1/A2 仍可能继续互相发消息对质（2026-08-14 华虹宏力轮首次出现，前七轮未见）。这些互驳**质量很高**——本轮产出三条实质修正：①「PE 看变便宜/PB 看变贵」是伪矛盾（BVPS 摊薄是同一控制下按账面而非评估值并入、不确认商誉的会计产物，与 ROE 提升同向）；②全口径净利与归母净利符号相反（少数股东吸收亏损）；③正常化 ROE 双路径锚。

**但控制者不得转发未收敛的中间结论**：本轮我把 A2 的框架转给正在写稿的 B，A1 随后推翻它，我不得不再发一条作废通知——B 白写了一段又改回来。

**Why**：Phase A 闸门只验「文件是否落盘」，不验「跨路结论是否已对质收敛」。先收工的路把中间结论发给仍在跑的路，双方要几个回合才稳定，而这几个回合发生在 Phase B 已开写之后。

**How to apply**：
- 放行 Phase B 前，若发现两路结论有冲突，**主动开一轮对质并等其收敛**再放行，而不是放行后边写边转。
- 确需在途转发时，明确标注「**此为未定稿的跨路结论，以 A1 最终版为准**」，让写手先不落笔。
- Phase A 收工后给各路发**停手令**（互驳不会自动到达写手，只有控制者转发才会到，继续往返纯属消耗）。
- 提醒先收工的路：其 evidence 文件的**尾部汇总区**容易与文中修正失步（本轮 A2 改了 §7.5/§7.7 但尾部仍是旧措辞），审查员会读到自相矛盾的材料——须在审查提示里预先声明哪些是已撤回的过时表述。

相关：[[review-before-phasec-false-critical]]、[[subagent-report-needs-explicit-request]]

## L3 自报时间戳与自报善后动作均不可信，亲验对象永远是文件

**规则**：subagent 的 `start`/`end` 时间戳、完成消息里的数字与"已纠正 XX"的裁定，均可能与它自己刚落盘的
文件内容矛盾，且错的往往是消息/自报值而非文件。控制者的耗时账与事实核验一律以文件（内容 + mtime + report
的 `end:` 时间戳）为准，subagent 的口头汇报只当"活着"的信号。

**机制**：仅措辞

**案例**：

（mode-deep.md「收尾（控制者本人）」段，自报时间戳失真部分）

**先算耗时账**：**以控制者自己记录的派发/收回时刻为准**（每一棒派发时打点、收到回复时打点），
六份 report 文件的 `start`/`end` 头（`phaseA1`/`phaseA2`/`phaseA3`/`phaseB`/`review`/`phaseC`）仅作
交叉参考——自报时间戳已被证伪不可信（2026-08-09 紫金实跑中审查 subagent 产出 19KB 完整报告却自报
耗时仅 1.4 分钟，明显是收工时补记的）。发现自报值与控制者记录相差超过 2 倍，要在耗时账里注明该棒
自报失真。汇总成一行报给用户，格式例：`A1 x / A2 y / A3 z（并行取最大）+ B + 审查 + C ≈ 合计`。
**这是"提速是否真的发生"的唯一可证伪依据**，不许省。

……

**自报时间戳继续被证伪（第二次）**：本轮审查 subagent 自报 `end: 10:48:30`，但其完成消息在控制者
10:44:42 打点前就已送达。**耗时账一律以控制者侧派发/收回记录为准**（dispatch.md §0.1 已有此约定）。

（dispatch.md §0.1 自报时间戳段）

**⚠️ 自报时间戳不可信**：2026-08-09 紫金实跑中，审查 subagent 产出 19KB / 133 行的完整报告，却自报
耗时仅 1.4 分钟——明显是收工时才补记的 `start`，而非开工时真实打点。`start`/`end` 头**只作参考**，
不可单独作为耗时账的依据。**控制者必须自己记录每一棒的派发时刻与收到回复时刻**，以控制者侧的记录
为准；subagent 自报值仅作交叉参考。**两者相差超过 2 倍时，以控制者记录为准，并在耗时账里注明该棒
自报失真。**

**控制者侧**：不等消息、不追要报告，subagent 结束后直接 `Read` 对应文件。收尾时以**控制者自己记录的
派发/收回时刻**为准汇总成一行耗时账报给用户（这是"提速是否真的发生"的唯一可证伪依据），report 里的
`start`/`end` 仅作交叉参考。

**为什么顺带加固了可信度**：subagent 的口头汇报本就不可信（已有教训：Phase A 曾自报"一次性脚本已删"
而实际未删）。落成文件后，控制者的亲验对象从"它说了什么"变成"它写了什么 + 我自己查到什么"。

（memory `subagent-message-contradicts-its-own-file.md` 核心判断）

subagent 的**完成消息正文**可能与它自己刚写的 evidence 文件**数字互相矛盾**，而且错的是消息、对的是文件。2026-08-19 普冉轮 A1 实测两次：① 消息报「H1 毛利率 45.18%、少数股东损益 2.3389 亿」，文件是「51.15%、4.8334 亿」（控制者拉半年报 PDF 原文核，文件对）；② 消息报「兆易 H1 归母 10.19 亿，A2 的 68.57 亿是把营收误读成归母」，文件 §7 是「营收 115.658 亿、归母 68.568 亿、扣非 48.830 亿」（A2 原本就对，消息凭空造了个反转）。控制者据消息②写进 Phase B 派发提示的裁定是错的，靠会话中断被迫重派才没进正文。

**Why:** 这比 [[subagent-report-needs-explicit-request]]（只回 idle 不给正文）更隐蔽——消息**有**正文、读着自洽、还带"已纠正 XX"的权威语气，容易直接采信。根因像是收工时凭记忆重述而非从文件回读。

**How to apply:** 控制者的亲验对象**永远是文件内容**，消息只当"活着"的信号。派 Phase B 前把 A1 文件里要引用的关键数字**逐条落地核一遍**（能拿到一手 PDF 就拉原文比对，见 [[phasea-numbers-need-authority-lane-adjudication]]）。**发现消息与文件冲突时，别只改冲突那一条——整条消息都要作废重读文件**，因为同一条消息里的其他"裁定"同样不可信。派发提示里凡引用 A1 结论处，注明"以 evidence 文件为准，A1 口头汇报作废"。

## L4 跨路校准是常态非例外，Phase A 按「最慢路 + 1~2 轮校准」预估

**规则**：先收工的路报出跨路校准需求会打破 Phase A 的深度上限，把墙钟从「三路取最大」拖到「最慢路 + 校准轮」。
这是三路并行的常态而非例外，派发时就该按此预估。

**机制**：仅措辞

**案例**：

**两轮校准把 A1 从约 13min 拉到 26.8min，但两轮都必要**：第一轮纠正合并前提，第二轮补「半年报今日披露、
须取全文正式数」（由 A3 报出）。Phase A 墙钟因此完全由 A1 决定（A2 13.0 / A3 15.0 早已收工）。
这是继藏格轮之后**第二次**观察到「先收工的路报出跨路校准需求 → Phase A 变成最慢路 + 校准轮」（雷赛轮为**第三次**：A3、A2 先后收工各报出一批裁定项，A1 由约 13min 延到 23.8min），
可视为三路并行的**常态而非例外**：派发时就该按「最慢路 + 1~2 轮校准」预估，而不是按三路取最大。

**控制者追加的跨路校准轮会打破 Phase A 的深度上限**：藏格的 A2 先收工（9.4min），报出三条需 A1 裁定的
硬数字问题（分红量纲 10 倍误读、钾储量缺口、锂产量指引两口径冲突），控制者用 `SendMessage` 追加给仍在跑的
A1 → A1 从 9.0min 延到 15.4min（自报），Phase A 墙钟被单路拖到 18.4min。**这笔钱花得值**（三条全部改变了
Phase B 的建模输入：30.78 亿 vs 307.8 亿、19-22 年静态年限、1.65 万吨权益口径），但**派发时要预期到**：
先收工的路一旦报出跨路校准需求，Phase A 就不再是"三路取最大"，而是"最慢路 + 校准轮"。

## L5 控制者派发时给出的前提本身可能错，一律写成「待核实假设」且三路都给

**规则**：控制者的前置观察（哪怕基于实测数据）只是假设，不是事实。派发提示应写成「我的推断是 X，请核实
X 是否成立」而非「事实是 X，请核实进度」，且三路都要给同一个待核实假设，让它们有机会互相证伪控制者。

**机制**：仅措辞

**案例**：

**控制者派发时给出的「前提」本身可能是错的，跨路校准要能反向修正控制者**：本轮控制者据「两只仍独立交易」
推断合并「尚未完成」，写进了 A1 的必查清单；先收工的 A2 查出真相是**合并已于 2025-12-09 终止**（方案未走到
任何审批节点）。控制者立即 `SendMessage` 把前提纠正推给仍在跑的 A1，A1 据此把估值分母锁死为 standalone
并否掉备考股本。**若无这轮校准，A1 会带着错误前提去查「审批进度」，Phase B 的估值分母可能用错**。
教训：控制者的前置观察（哪怕基于实测数据）只是**假设**，派发时应写成「我的推断是 X，请你核实 X 是否成立」
而非「事实是 X，请核实进度」——本轮恰好写成了后者，靠 A2 独立采证兜住。

**光智轮是迄今最强的一次印证**：控制者据 PB 46.76、市值 356 亿而隐含净资产仅 7.6 亿，推断「先导电科重组
仍在推进但未并表」并写进三路提示——**事实是该重组早在 2025-06-27 就已终止**，2026 年的真实标的是完全不同的
另一家公司（先锐科技/磷化铟）。**三路里最先收工的 A3 独立查出并主动上报，控制者才得以在 7 分钟内把纠正推给
仍在跑的 A1、A2**。这一轮控制者的推断**方向对（确未并表）但标的全错**，说明「用可观测数据反推出的前提」
即便自洽也可能指向错误对象——**派发时一律写成待核实的假设，且三路都要给，让它们有机会互相证伪控制者**。

## L6 会话中断杀掉全部 subagent；别把「到点再做」交给它；能亲自接棒就别等

**规则**：agent 没有定时器，只能 idle 等消息，而 idle 状态活不过会话边界；需要等待/定时的动作要么控制者
自己做，要么接受后台命令同样可能被会话终止打断。会话中断后不要重派要重建全部上下文的棒，能自己接棒就自己做。

**机制**：仅措辞

**案例**：

**会话中断会杀掉全部 subagent，控制者必须能亲自接棒**：天岳轮 146min 里有 **60min 是会话边界造成的空档**——A1 被派去"等 09:30 开盘后取财报后行情"，转 idle 等待期间随会话终止，那一棒**永远没有交回**。控制者恢复后不是重派 A1（要重建全部上下文），而是**自己用 20 行脚本直取腾讯行情 + 复算全套锚**，3min 闭合。教训有两条：① **别把"到点再做"的任务交给 subagent** —— agent 没有定时器，只能 idle 等消息，而 idle 状态最脆弱；需要等待的动作要么控制者自己做，要么用后台命令做计时器（但后台命令同样活不过会话边界）。② **Phase B 若被中断，续跑不必重派完整写手**：本轮草稿已落盘 997 行、只剩 10 处 `【待锚】` 占位，控制者派了一个**只填占位的收口棒（B-2）**，给它"完整读一遍现有档 + 只填这 10 处 + 不重写任何已有内容"的指令，5.3min 收工。**把长文撰写拆成"主体"与"填锚"两段本身就是抗中断设计**——只要主体先落盘，任何中断都只损失填空那一小段。

## L7 静默失败须配探测点，else 分支也要发信号

**规则**：`idle_notification` 的缺席不代表还在跑——沉默不等于进行中。凡需等待的东西都要配一个覆盖失败
路径的探测点，只报成功的探测器在 crashloop 与「还没好」之间无法区分；agent 不可达时重派远快于追问。

**机制**：`deep_redo_gate.py` + `until` 包装

**案例**：

**subagent 与后台任务都会静默失败，探测点必须覆盖失败路径**：光迅轮 147min 里有 **64min 是纯空转**（十轮中最大的单笔无产出损耗），因为两个失败**同时**发生且都无声：① 首次派的审查 subagent 跑了 66min **无任何落盘、无报错**，最终 `SendMessage` 才报 "No agent named … is reachable"（会话已终止）；② 用来等开盘取价的后台 Bash 任务以 **exit 4** 失败，同样没有中间信号。控制者当时在「等两个已经死掉的东西」。**教训：`idle_notification` 的缺席不代表还在跑——沉默 ≠ 进行中。** 凡需等待的东西都要配一个**覆盖失败路径**的探测点：

```bash
F="<产物路径>"; T=1200; E=0
until [ -f "$F" ] || [ $E -ge $T ]; do sleep 15; E=$((E+15)); done
if [ -f "$F" ]; then echo "DONE after ${E}s"; else echo "TIMEOUT after ${E}s — 可能静默失败，需控制者接管"; fi
```

关键是 **else 分支也发信号**——只报成功的探测器，在 crashloop 与「还没好」之间无法区分（与 Monitor 的「silence is not success」同源）。另一半教训：**agent 不可达时重派远快于追问**——光迅轮重派的审查 **4.0min** 就交出完整两段报告，而首次那个等了 66min 一无所获。**与天岳轮的「会话中断」教训合看**：subagent 的死法不止一种（会话边界、静默崩溃、后台任务非零退出），但**控制者的应对是同一条——能亲自接棒就别等**。光迅轮的价格更新、§9.10 补写、Critical 修复最终都由控制者直接做，合计 10min，比任何一次重派都快。

## L8 跨日价格锚刷新的盲区是二次计算而非字面量，派生句必须逐句手算

**规则**：刷新价格锚后，grep 字面量只能覆盖一次引用；凡出现「反推」「隐含」「对照当前市值」「= 市值 ÷ X」
「相当于 X 倍」句式的段落，必须逐句手算一遍，不能靠替换表。

**机制**：`deep_redo_anchor_audit.py`

**案例**：

**跨日重启时，价格锚刷新的盲区是「二次计算」而非字面量**：雷赛轮因会话跨 3 天中断，恢复时现价已从
60.64 跌到 54.20（−10.6%），控制者亲自做了 71 处锚点替换并 grep 自查残留干净——**审查仍抓出 4 处 Major，
控制者复核时又自查出第 5 处**。五处全部是**用旧市值反推的派生数**，共同特征是**句子里不含任何旧锚的字面量**，
grep 扫不到：① 前瞻 PE（`市值 / 2026E 归母`，三个数全错）；② 「市价隐含的机器人期权价值 50~90 亿」
（= 旧市值 − 主业估值区间，正确应为 31~71 亿）——这条影响面最大，是「AI 叙事已被充分定价」论证的核心量化
支撑，且被 §11 风险清单复用；③ 「反推现价所需的正常化 owner earnings 9.13 亿 / 2.85 倍」（同一张表的上一行
已正确用新市值算出 g，**同表自相矛盾**）；④ RIM 交叉验证表 bear 行公式代入错误（与刷新无关的孤立失误，
但同一次审查一并抓出）；⑤ 风险节里的「配合 79x 的 PE」。
**铁律**：刷新价格锚后，grep 字面量只能覆盖**一次引用**；凡出现「反推」「隐含」「对照当前市值」「= 市值 ÷ X」
「相当于 X 倍」句式的段落，**必须逐句手算一遍**，不能靠替换表。**代价参考**：刷新本身 12min，
遗漏订正另花 2min + 一轮审查——**若跳过审查直接提交，这 5 处会带着错数字入库**。
**另一半教训**：跨日重启第一件事是**复核基本面基线是否仍成立**（本轮用 `ak.stock_financial_abstract_ths`
确认最新报告期仍为 2026-03-31、三日内无新增定期报告，故三情景每股内在价值不动、只重算安全边际）。
若期间恰好落了财报，就不是刷新锚而是实质返修，成本量级完全不同。

## L9 「撞财报日」的代价取决于财报落在 Phase A 之前还是之中

**规则**：不是「重审窗口落在财报日 ±3 天」就一律按 70-90min 预估，而要看采证时点是否晚于财报披露时点——
晚于则按常规甚至更省，早于或跨越财报发布则按 70-90min 并预期 Phase B 返修一轮。

**机制**：仅措辞

**案例**：

**「撞财报日」的代价取决于财报落在 Phase A 之前还是之中（海光轮修正了联想轮的结论）**：联想轮 79min 之所以贵，
是财报在**Phase B 撰写途中**由 A1 补出，推翻已写进初稿的口径 → 在途全档返修；海光轮同样撞财报日（2026 半年报
当日盘后披露），却只用 58min 且**零返修**——因为控制者派 Phase A 时**财报已经发布完毕**，A1 一次就取到完整
半年报，三路拿到的是同一份终局事实。**识别信号要细化**：不是「重审窗口落在财报日 ±3 天」就一律按 70-90min，
而要看**采证时点是否晚于财报披露时点**——晚于则按常规预估（甚至更省，因为财报把大量存疑数字一次性坐实），
早于或跨越则按 70-90min 并预期 Phase B 返修一轮。**盘后重审是本 skill 最划算的时间窗**。

**「撞财报发布当日」是目前观察到最贵的单一情形（79min，六轮最长）**：联想 FY26/27 Q1 恰在重审当日盘中发布，
三路采证同时撞上——A1 的"查是否已发布"变成取全套新财报、A2 的旧档 8 条论点有 6 条被当日财报冲击、
A3 的 lens 清单全部要按新季度重答。**代价不在 Phase A（17min 尚可控），而在 Phase B**：撰写者初稿完成后
控制者才收到 A1 补出的跨路裁定（推翻了两条已写进初稿的口径），触发**在途全档返修**，Phase B 单棒 27min
（六轮最长，vs 藏格 18.1）。**识别信号**：派 Phase A 前先查标的的财报日历，若重审窗口落在财报日 ±3 天内，
按 70-90min 预估，并预期 Phase B 会返修一轮。

## L10 财报盘后披露 + 次日盘前采证：市值分母整段留空、开盘后补锚

**规则**：采证时点晚于财报披露时点、但早于财报后第一个交易时段时，「财报已终局」与「价格未反映」同时
成立——把 §0/§9/§10 的市值分母整段留空、其余章节照写，开盘后补一次盘中锚再填，而不是等 6 小时收盘。

**机制**：`deep_redo_gate.py --phase B` 占位检查

**案例**：

**「财报盘后披露 + 次日盘前采证」是比海光轮更省的窗口，但要预算一次补锚**：天岳半年报 2026-08-19 21:46 盘后披露，Phase A 于次日 08:32 开工（A 股 09:30 才开盘）。好处是三路拿到的是**完整终局财报**（零返修，与海光轮同因）；代价是 **A1 能取到的最新行情是 8/19 收盘，那是财报披露"之前"的价格**——用它算安全边际，等于让分母不知道财报。处理办法不是等收盘（要等 6 小时），而是**把 §0/§9/§10 的市值分母整段留空、其余章节照写**，开盘后补一次盘中锚再填。识别信号：**采证时点晚于财报披露时点、但早于财报后第一个交易时段**——这时"财报已终局"与"价格未反映"同时成立，是唯一需要显式拆分撰写顺序的情形。

## L11 「等收盘」是可选自费项，对财报日标的值得

**规则**：非财报日、振幅平常的标的不必等收盘；但财报日标的振幅可能极大，盘中锚的说服力明显弱于收盘锚，
用一个后台脚本等收盘换来的估值分母确定性通常值得那几分钟空档。

**机制**：仅措辞

**案例**：

**「等收盘」是可选的自费项，但对财报日标的值得**：本轮 A1 只取到盘中价（HK$34.10），控制者用一个后台脚本
等到 16:00 收盘后落定终值（HK$35.00，+20.52%）。代价约 6min 空档（与审查并行、实际净损耗更小），
收益是**估值分母从盘中快照变成收盘价**——且当日振幅极大（29.60→35.46），盘中锚的说服力明显弱于收盘锚。
**副产品**：收盘 +20.52% 高于尾盘 +17.42%，直接推翻了撰写者用盘中价路径写的"市场把涨幅吐回去=怀疑票"
这条定性论据，逼出一条真实的方法论教训（数字上留了敏感度带、叙事上却把同一段不确定价格当成了确定事实，
双重标准）。**非财报日、振幅平常的标的不必等**。

## L12 附件型（.docx/.pdf）二值事实缺口由控制者亲自补证

**规则**：事实源是附件型（.docx/.pdf/.xls 名单、公告附表、交易所披露易 PDF）时 subagent 大概率卡住——
根因是能力盲区（WebFetch 解析不了二进制附件）而非不努力，控制者直接接手成本更低，别让它多试两轮。

**机制**：仅措辞

**案例**：

**「二值事实缺口」应由控制者亲自补证，别让 subagent 反复试**：中国白银轮的 A3 报出一个 P0 二值项
（公司是否在商务部白银出口白名单内——在＝政策 α、不在＝丧失出口通道的实质利空，方向相反，Phase B
无法在缺失下建模）。A3 连跑两轮仍只能给「未能核实」，**根因是能力盲区而非不努力：名单只存在于 .docx
附件里，WebFetch 只能把网页转 markdown，解析不了二进制附件**。控制者用 stdlib `zipfile` 直接读
`word/document.xml` 一轮闭合（先 WebFetch 拿附件下载链接，再 urllib 下载 + zipfile 解压）。
**识别信号**：事实源是**附件型**（.docx/.pdf/.xls 名单、公告附表、交易所披露易 PDF）时，subagent 大概率
卡住——控制者直接接手，成本约 3-5min，远低于让它多试两轮。**顺带产出**：拿到全名单后可做同业对照
（本轮发现湖南白银在列第 42 位、豫光/云铜/江铜/恒邦均在列，只有本标的不在），**这个对照比"在不在"
本身更有说服力**，是 subagent 即便查到也未必会做的二次利用。

## L13 亲验用精确锚点（tail + 关键词计数 + mtime + `end:`），别用模糊 grep

**规则**：验文件用精确锚点（tail 看真尾部 + 关键词计数 + 文件 mtime + report 的 `end:` 时间戳），
不用会误命中的模糊 grep；派发时也要把落盘位置写死（如"追加到文件末尾"）。

**机制**：`deep_redo_gate.py`

**案例**：

**控制者的亲验方法本身也会出错，锚点要精确**：本轮控制者用模糊 grep 关键词判断 A3 是否落盘补查节，
grep 命中了正文里另一处同词（"建议 Phase B 补查此项"）并从该处打印，输出被截断后**误判 A3 空手转
idle 并去催了一轮**——实际它已落盘，只是把新节插在倒数第二节而非文件末尾。教训：验文件用**精确锚点**
（`tail` 看真尾部 + 关键词**计数** + 文件 mtime + report 的 `end:` 时间戳），别用会误命中的模糊 grep；
**派发时也要把落盘位置写死**（"追加到文件末尾"），否则位置自由会让后续验证失效。
（另一半仍成立：subagent 的**增量任务**确实会被静默跳过，与"善后动作自报不可信"同源，亲验对象永远是
文件内容与时间戳，不是 idle 信号。）

## L14 Phase B 拆「主体 + 填锚」两段本身就是抗中断设计

**规则**：长文撰写拆成"主体"与"填锚"两段本身就是抗中断设计——只要主体先落盘，任何会话中断都只损失
填空那一小段；续跑时不必重派完整写手，只需派一个"完整读一遍现有档 + 只填占位 + 不重写已有内容"的收口棒。

**机制**：`deep_redo_gate.py --phase B` 占位检查

**案例**：

② **Phase B 若被中断，续跑不必重派完整写手**：本轮草稿已落盘 997 行、只剩 10 处 `【待锚】` 占位，控制者派了一个**只填占位的收口棒（B-2）**，给它"完整读一遍现有档 + 只填这 10 处 + 不重写任何已有内容"的指令，5.3min 收工。**把长文撰写拆成"主体"与"填锚"两段本身就是抗中断设计**——只要主体先落盘，任何中断都只损失填空那一小段。

## L15 非权威路的数字须送 A1 逐条核定量级/科目/期间/主体四项

**规则**：A2/A3 报的财务数字可能有 10 倍量级 + 科目双重错误，不论是否与已知数显性冲突，都要逐条送 A1
从原文核定量级、科目、期间、主体四项；A1 的第二波裁定必须在派 Phase B 前收齐。

**机制**：仅措辞

**案例**：

Phase A 非权威路（A2 论点 / A3 lens）汇报里的财务数字读起来和 A1 一样确定（带 URL、带出处），但可能整条错。2026-08-16 SkyHigh Memory 轮实测：A2 报「2026 预测**净利** 2.142 亿」，原文实为**营业收入 21.42 亿**（10 倍量级 + 科目双错）；「26H1 净利 1.721 亿」实为「2026 年 1–5 月**营收** 17.21 亿」（量级 + 期间 + 科目三错）。这两个数若入档会直接毁掉估值节的收入基数。

同轮 A1 还化解了一个看似的「量级冲突」：A2 与背景的净利数差一个数量级，真相是**两个法律主体**（SHM 单体 vs 诺亚长天合并，差额=并购贷款利息），双方都对——所以冲突不一定意味着有人错，也可能是口径未统一，须由权威路下「统一口径令」。

**Why**：A2/A3 的采证面是媒体与转述，媒体常把「营收」写成「净利」、把区间口径写错；A1 读的是重组报告书/问询回复原文。skill 已定「A1 是唯一权威数字源」，但实际执行时容易只在**冲突显性化**时才裁定，而单位/科目错误往往**不显性**（数字自洽，看不出问题）。

**How to apply**：控制者收到任一非权威路报出的财务数字后，**不论是否与已知数冲突，都逐条 SendMessage 给 A1 要求「从原文核定量级、科目、期间、主体」四项**；A1 收工后若发来第二波裁定消息，**务必在派 Phase B 前收齐**（SkyHigh 轮早派 2 分钟，靠在途校准补救）。

**更普适的判据（2026-08-20 光迅轮再犯，且更严重）**：控制者发出校准消息后，A1 报的「收工」**只对它当时手上的任务有效，对尚未读到的校准项无效**——光迅轮 A1 08:48 报第一轮收工，控制者亲验文件后 08:53 放行 Phase B，但 08:50 前发出的校准仍在它队列里，它随后又跑 13min 第二轮，产出两条改变正文写法的硬发现（存货增量的原材料拆解、定增曾降价 19% 才发满下限），全程与 Phase B 重叠。**「文件已落盘 + 数字有 URL」这个亲验通过，不等于闸门可以过**——还要问「我发出的校准它读到了吗」。二选一：**要么等它明确回复「校准项已闭合」再放行，要么主动接受重叠并准备好在途推送**；最坏的是以为串行、实际重叠。Phase B 提示里要写明「某某数字是错的，禁止入档，只允许出现在『X 路原报→A1 核定』的显式标注块内」，并要求撰写者跑脚本自查该数字出现次数。相关：[[subagent-report-needs-explicit-request]]、[[cross-lane-debate-converge-before-relay]]

## L16 「前提变化」警报先 grep 另两路 evidence 再决定要不要派校准轮

**规则**：某一路报「前提变了，另两路可能建立在错误假设上」时，**先 grep 另两路已落盘的 evidence 文件**
确认它们是否已自发命中；命中就直接放行，别派校准轮。

**机制**：仅措辞（可用一条 grep 落地）

**案例**：

2026-08-23 优刻得轮，触发变量是「二季报」。派发时半年报尚未在任何一路的视野里被确认，法定截止日是 08-31，
旧档明确记着「2026H1 至今未披露」。A3 先收工，开篇顶格写了一条警报：**半年报已于 08-22（周六）披露**，
并附 PDF 链接 + 核心数，明确提示「若 A1/A2 是按『半年报未出』的假设开展的，需要回补」。

这条警报在形式上完全符合 L15 描述的跨路校准场景——按 mode-deep.md 的预估口径，跨路校准在十三轮里出现过四次、
是常态，控制者的默认反应应该是立刻 SendMessage 给 A1/A2 通报前提变化。

**但派校准前先花两条 grep 查了另两路已落盘的 evidence**：

```bash
grep -n "2026-08-22\|9\.82\|807\.72\|1,685" .omc/artifacts/<股票名>-<日期>-evidence-A1-数据锚.md
grep -n "2026-08-22\|9\.82\|807\.72\|1,685" .omc/artifacts/<股票名>-<日期>-evidence-A2-论点.md
```

A1 命中 28 处、开篇即写「本轮头号发现：半年度报告已于 2026-08-22（昨日）披露」；A2 命中 24 处、
标题就是「本轮最重要的一次性事实：2026 半年报已于 2026-08-22 披露」。**三路各自独立联网、各自独立发现，
自发收敛。** 校准轮没派，Phase A 直接过闸。

**Why**：一路报「前提变了」时，它只知道**自己**的前提变了，它无法看到另两路的 evidence 文件——
它的警报措辞（「若 A1/A2 是按……假设开展的」）本身就是一个**条件句**，不是一个已核实的事实。
而三路拿的是同一个标的、同一个日期、同样的「必须联网实时核实」指令，**对于一个已公开披露的一级事实
（财报、公告、重大事件），三路自发命中才是常态，漏掉才是例外**。跨路校准真正必要的场景是 L15 那种
——某一路**报出了错误的数字**（量级/科目/期间/主体错），需要权威路裁定；那是「有人错了」，
而不是「有人可能不知道」。两者不能混为一谈。

派一轮不必要的校准不只是浪费墙钟：SendMessage 会把已收工的 subagent 重新唤起跑一轮，
A1 那种最重的一路可能再跑十几分钟，且**新一轮产出会与 Phase B 重叠**（L15 后半段光迅轮的坑）——
本可串行的流程被自己搅成重叠。

**How to apply**：收到任一路的「前提变化/需要回补」类警报时，按这个顺序处理——
① **先 grep 另两路 evidence 的特征串**（新事实的日期、几个关键数字），不 grep 就不判断；
② 命中 → 直接放行，并在耗时账里记一句「A3 报前提变化，grep 确认三路已自发收敛，未派校准轮」；
③ 未命中 → 再按 L15 派校准，并接受「要么等它回复已闭合、要么准备在途推送」的二选一。
判据一句话：**「另两路知不知道」是可以自己查的，不要用一轮 subagent 往返去查一件 grep 两秒能查的事。**
相关：[[L15]]、[[subagent-message-contradicts-its-own-file]]

## L17 平铺档迁文件夹档时，`events.md` 不是「新建空档」而是「迁移事件关联」

**规则**：目标此前是**平铺档**时，派发 Phase B 不可照抄「`events.md` 不存在才新建 `related_docs: []`」。
先数旧平铺档 related_docs 里有几条**事件 theme**，把它们连同 note 一并交给 Phase C 迁进 `events.md`，
并把这些 theme 的反向链改指到 `<股票名>/events.md`（不是 `index.md`）。

**机制**：仅措辞（控制者派发时按「旧档事件 theme 条数」二分即可落地）

**案例**：

2026-08-23 士兰微轮，目标是平铺档 `2026-06-19-士兰微-buffett分析.md`，其 related_docs 有 10 条：
7 条事件 theme + 3 条结构性（华润微/扬杰/comps）。

派发 Phase B 时照抄了 mode-deep.md 默认参数表里的「`events.md` 不存在才新建 `related_docs: []`」，
写手**如实照办**，落盘了一个空 events.md。**规格本身没错，错在适用场景**——那条规则的本意是
「重做时别覆盖 news-impact 累积的回写」，针对的是**目标已是文件夹档**的情形；而迁移场景下
「不存在」恰恰是因为文件夹是新建的，不代表这只股没有历史事件关联。

后果若不拦截：`buffett-doc-spec` 明写「index.md 的 related_docs 只放结构性引用，**事件 theme 一律在
events.md**」，所以 7 条事件 theme 既进不了 index.md、又没被写进 events.md，Phase C 删掉旧平铺档后
就是 **7 处死链**，且 refs lint 未必抓得到（见 memory `refs-lint-misses-inline-body-links`）。

**是写手在 Phase B 汇报的「留给 Phase C 的注意事项」里顶格标为「本轮最大的一处收尾风险」才被拦下的**——
控制者当时正准备直接派 Phase C。回查 `buffett-doc-spec` §文件布局表确认写手判断成立，遂在 Phase C 派发里
补了「任务 A」：把 7 条 theme 连 note 迁进 events.md（路径 `../../../../themes/`），
B-1 组 7 份 theme 改指 `士兰微/events.md`、B-2 组 3 份结构性档改指 `士兰微/index.md`，两组分开给。

**附带的一条**：迁移时旧 note 里的数字（旧档的 PB / 安全边际 / 期望内在价值）多已过时，
迁移动作正是更新它们的唯一时机——本轮顺手把中芯档 note 里的「PB 5.71x」改成 4.90x、
并把已被控制者判为分歧项的「未推动涨价」改成分歧措辞。**迁移 ≠ 原样搬运。**

## L18 `lint_docs_refs.py --rewrite-blocks` 在有 violation 时提前 return，根本不重写

**规则**：`--rewrite-blocks` 必须排在「补完反向链」**之后**跑。在还有 asymmetric ref 的状态下跑它，
它会打印 `FAIL: N violation(s)` 然后 `return 1`，**一个字节都不改**，且因为 `--rewrite-blocks`
的成功输出是 `Rewrote N file(s)`、失败输出是 violation 列表，两者长得完全不像，很容易把
「没重写」误读成「重写了但仍有别的问题」。

**机制**：仅措辞（`finalize.md` 动作清单本就是「步骤 3-4 反向链 → 步骤 5 双 lint」的顺序，
本条只是把「为什么顺序不能颠倒」写出来）

**案例**：

2026-08-24 扬杰轮，控制者在合并审查后自修 Minor（压缩 `index.md` 的 4 条 related_docs note
以瘦身），改完 frontmatter 后立刻跑 `--rewrite-blocks` 想让 auto-block 跟着缩，
输出重定向到了 `/dev/null`，只看体积——**18,880 字节纹丝不动**。
复查发现 frontmatter 是新短 note、auto-block 仍是旧长 note，**同一文件里两份 note 打架**。
读 `lint_docs_refs.py:155-163` 才看清：`if violations: ... return 1` 在 `if args.rewrite_blocks:`
**之前**，当时全仓恰有 8 条 violation（正是本任务待补的 8 条反向链），所以重写分支从未执行。

**处置**：不是 bug，是设计——先保证引用图自洽再渲染。正确做法就是遵守 `finalize.md` 的既有顺序，
把 auto-block 的重生交给 Phase C；控制者阶段改 frontmatter note 后**不必也不该**自己补跑重写。
**副产品**：控制者若在此处误判为「脚本坏了」而手编 BEGIN/END 块，就会踩到
`finalize.md` 明令禁止的「别手编 auto-block」。

## L19 审查员报的「两路 evidence 数字冲突」，先核是不是同一张表的不同列

**规则**：收到「A1 与 A3 对同一事实给出方向相反的数字」这类 Major 时，控制者的第一动作不是
按「以 A1 为准」机械取值，而是**把两份 evidence 的原始表格拉出来对齐列名**——财务报表附注里
同一行常有「期初余额 / 本期增加 / 本期转固 / 期末余额」四列，两路各摘一列就会看起来矛盾。
是口径差就补一句区分说明，不是改数。

**机制**：仅措辞

**案例**：

2026-08-24 扬杰轮，审查员报 M2：A1 说「越南在建工程 H1 **净减少 570 万**」，正文（采自 A3）说
「越南生产基地 H1 **净增 0.583 亿**」——方向相反、量级差 10 倍，且 `sources.md` 还写着
「本档未出现无法调和的冲突项」，审查员据此定为 Major（红线 6 程序性缺陷）。审查员自己也留了活口：
「也可能根本不是同一统计口径」。

控制者把两份 evidence 的在建工程表并排拉出来，一眼看清：A3 抄的是完整 roll-forward
（预算 6.197 亿 | 期初 2.454 | **本期增加 0.583** | 本期转固 0.630 | 期末 2.397），
A1 抄的是期末 vs 期初两列（2.397 vs 2.454 = **−570 万**）。**2.454 + 0.583 − 0.630 ≈ 2.397，
两个数字同时成立**，根本不冲突。

**处置**：不改任何数字，在 `thesis.md` / `valuation.md` 两处把两个口径并列写出
（「本期增加 0.583 亿 − 转固 0.630 亿 → 余额净减 570 万，是七个重要在建项目中唯一余额下降者」），
并把 `sources.md` 那句「未出现无法调和的冲突项」改成显式记录这处**已裁定的口径差**。
**顺带发现余额净减比净增是更强的证据**——它坐实了「资本确实在撤出海外」，比只说「本期还在投」有力，
所以这次核对不只是消歧义，还捡回了一条论据。

## L20 `--rewrite-blocks` 的前置不只是「补完反向链」，还包括「旧档已从磁盘消失」

**规则**：Phase C 里 `lint_docs_refs.py --rewrite-blocks` 必须排在**待删旧档物理删除之后**，
不只是排在「反向链改指之后」。因为待删的平铺旧档自己也带 `symmetric: true` 正向条目——
你把兄弟档的反向链改指新文件夹档的那一刻，**旧档的正向条目就失去了对应的反向条目**，
全仓立刻多出 N 条 asymmetric violation，`--rewrite-blocks` 照例提前 return（见 [L18]）、一字不改。
`finalize.md` 步骤 2（删旧档）在步骤 5（重生块）之前不是排版巧合，是硬依赖。

**与步骤 10「删增必须与 commit 同一条命令链」的调和**：先用 `rm` 把旧档从工作区拿掉跑 lint，
提交时再在同一条链里用 `git rm -q --ignore-unmatch <path>` 补暂存删除——`--ignore-unmatch`
存在的意义正是「文件已不在磁盘时也不报 pathspec 错」，两条约束因此并不冲突。

**机制**：仅措辞（`finalize.md` 步骤 5 已补 `[L20]` 引用点明该前置）

**案例**：

2026-08-24 小鹏集团轮（平铺档升七文件文件夹档）。控制者接手失败的 Phase C 后，按 finalize.md
先改完三份兄弟档（零跑 / 理想 / cross-sector 对比档）的反向链指向 `小鹏集团/index.md`，
随即跑 `--rewrite-blocks`，输出：

```
2026-08-08-小鹏汽车-buffett分析.md: asymmetric ref to ...2026-08-08-零跑汽车-buffett分析.md
2026-08-08-小鹏汽车-buffett分析.md: asymmetric ref to ...2026-06-20-理想汽车-buffett分析.md
2026-08-08-小鹏汽车-buffett分析.md: asymmetric ref to ...2026-08-08-小鹏-零跑-全球业务对比.md
FAIL: 3 violation(s)
```

三条 violation **全部由待删的旧档发出**，且是「反向链改对了」这个正确动作**直接制造**的——
改之前旧档与三兄弟互指、图是自洽的；改之后旧档变成单向悬空。`rm` 掉旧档后原地重跑，
`Rewrote 6 file(s)` + 双 lint 双 exit 0 + 孤儿检查里新档不在列表，一次通过。

**误判风险**：这三条 violation 的文件名指向的是**本任务的待删档**，很容易被并行 session 场景下
「违规不指向本任务文件即视为通过」的判据（见 memory `parallel-session-lint-gate`）**反向误伤**——
它明明指向本任务文件，却既不该修也不该等，正确处置是**继续往下走完步骤 2 的删除**。
判据要连着「这条违规是否会被后续步骤自然消解」一起看，不能只看文件归属。

## L21 控制者在返修单里提出的**新事实性论断**绕过了 A 路证据链，subagent 会照写不误

**规则**：审查后的返修单里，控制者可以下"结构/格式/交叉链接/补解释"一类指令，但**凡是引入新的
事实或因果论断（"X 会导致 Y"、"该假设偏乐观"），都等于往档里塞一条没走过 Phase A 采证的证据**。
写手默认服从控制者框架、不会反驳，于是错误论断被原样写进正式档。**下写入令之前，这类论断必须
先经一路验证**——或者改成派发体例里本来就有的写法：「我的推断是 X，**请核实 X 是否成立**」
（[L5] 对 Phase A 的要求，返修阶段同样适用），而不是「请补写 X」。

**机制**：仅措辞（`mode-deep.md` 合并审查段已补 `[L21]` 引用）

**案例**：

2026-08-24 中钨高新轮。写手用「矿端 ≈ 0.63P − 1.8」的线性函数处理资产注入。控制者在派发审查单
时提出质疑「矿山现金成本不随钨价等比下降，线性模型在低价区会系统性高估 bear 档」，并在收到
CHANGES-REQUESTED 后把它写成**必改项**下发：「补一段明写 bear 14.5 亿有被系统性高估的风险
+ 给量化敏感性」。

写手照做，把整段论证 + 三行敏感性表（含 262.1 / 258.7 / 4.61 / 4.11 等派生数）写进 `valuation.md §9.2(a)`。

**但这条论断是错的**，而且与档案**自己的标定表**矛盾：
1. 利润 = 产量 ×（价格 − 单位成本）− 固定成本，在产量与单位成本不变时**本就是价格的线性函数**，
   `0.63P − 1.8` 的**负截距正是固定成本的载体**——成本刚性不是线性模型的敌人，恰恰是它的来源。
   会随价格下跌加速恶化的是**百分比毛利率**，不是绝对利润。控制者把两者混了。
2. bear/base/bull 取的 P = 25/40/50 **全部落在两个标定点 21.12 与 69.04 之间，是内插不是外推**；
   且 bear 的 25 **高于**已观测低点 21.12，而那一点上两矿实际净利 11.54 亿是**实测值**——
   bear 矿端被观测数据从下方兜住，不存在"低价区被高估"。
3. 真正该点名的脆弱处是另外三条独立假设（产量不变 / 单位成本稳定 / 副产品价格不背离），
   写手初稿在 §9.2(a) 限定条款里**本来就写了**。

是**审查员在复核轮主动推翻控制者**才拦下：它重算后把该项从 Major 降为 Minor 并给出上述理由。
控制者确认后撤销该修项，改为只加一个指向 `business.md §3.4`（已有的正确版本）的交叉链接。

**连带教训（复用 memory `subagent-message-contradicts-its-own-file`）**：本轮写手连发两条
**陈旧完成消息**——一条说"已完成修 4"（其实随后已按更正撤销）、一条说"已在 §8.1 加口径提示"
（文件里没有）。两次都是消息在文件之后/之前定格。**亲验对象永远是文件**：控制者两次 Read
才拿到真实状态，其中一次还先因 cwd 被前序 `cd` 污染而误判"A1 仍在跑"（Bash cwd 跨调用持久，见 `.claude/rules/dev-environment.md`），改用绝对路径后才看到文件早已落盘。

## L22 账号会话额度耗尽会**同时**杀掉全部在途 subagent；探测点超时 ≠ 任务失败，须分辨"死在交付前"还是"死在交付后"

**规则**：subagent 失败消息里的 `You've hit your session limit · resets <时间>` 是**账号级**限制，
不是单个 agent 的问题——**同一时刻所有在途 subagent 一起死**，且重派必然同样失败。
此时**不要等额度重置**（本轮距重置 3 小时），按 [L6]「能亲自接棒就别等」由控制者亲自接棒。
接棒前先按交付物分辨每个死掉的 agent 处在哪一侧：
- **死在交付后**（产物已落盘）→ 零损失，直接用它的产物继续；
- **死在交付前**（report 文件不存在）→ 该阶段整段要控制者自己重做。

**探测点的超时分支必须能区分这两种情况**（[L7] 要求超时分支也发信号，本条再加一层）：
`until [ -f <report> ] || [ $n -ge N ]` 收到的 `TIMEOUT` 只说明文件没出现，**不说明 agent 死没死**。
控制者看到 TIMEOUT 后要做两件事：① `ls` 该阶段全部产物（不只 report），② `ListAgents` 看 agent 状态。

**机制**：仅措辞（`mode-deep.md` 合并审查段与 Phase B 段的等待处已带 [L7]，本条并列引用）

**案例**：

2026-08-25 零跑汽车轮。Phase B 写手与合并审查员在 03:04:57 / 03:05:13（相隔 16 秒）**同时**
以 `failed / You've hit your session limit · resets 2:10pm` 结束。两者处在分界的两侧：
- **Phase B 已交付**：七文件 + `phaseB-report.md` 全部落盘（闸门 `--phase B` 已 exit 0），零损失；
- **审查员死在写 report 之前**：`review-report.md` 从未存在，探测点报的是 `REVIEW_TIMEOUT_22MIN`。

控制者据此只重做了审查一段（自己读七文件 + 三份 evidence 做完整审查，并把结果补写成
`review-report.md` 存档，注明执行者是控制者本人及原因），Phase B 的产物原样沿用，随后自己做完 Phase C。
**若当时误把 TIMEOUT 读成"审查还在跑"而继续等，会白等 3 小时；若误读成"整轮失败"而重派 Phase B，
会丢掉一份已经合格的成稿。**

## L23 对**仍在写盘**的 subagent 产物做 grep 抽样，会读到中间态并据此误判

**规则**：控制者在 subagent **还没结束**时 grep 它的产物做抽查，拿到的可能是写了一半的版本。
据此下的判断（"它没采纳我的修正"）会是错的，且会导出一份不必要的返修单。
**亲验必须在 agent 结束之后，且对关键结论要整文件读、不能靠关键词抽样**——
grep 命中的行不带上下文，一个同时出现新旧两种口径的过渡态文件，抽样结果完全取决于命中了哪一行。
（与 [L13]「亲验用精确锚点」互补：L13 讲锚点要精确，本条讲**时机**要在结束之后。）

**机制**：仅措辞

**案例**：

2026-08-25 零跑汽车轮。控制者在 Phase B 开工后才收到 A1 第二轮裁定，其中一条推翻了原派发的
主口径（主业可比亏损从"双剔 −17.03 亿"改为"仅剔碳积分 −6.42 亿"，双剔降为最严格下界），
遂 `SendMessage` 补发修正。为确认写手是否采纳，控制者在写手仍在运行时 grep `'17.0'`，
命中 `| **双剔（正确口径）** | −17.21 | −17.03 |`，据此向用户报告"写手确实未采纳后发修正"。

**实际是采纳了的。** 写手结束后整文件读，`business.md §3.2` 与 `valuation.md §9.1` 均已改写为
「① 仅剔碳积分（本档主口径）」+「③ 双剔 —— 最严格下界」，`index.md` 的 frontmatter 与 §0 也都用
新主口径。grep 命中的是修正落盘前的过渡态。控制者随后当着用户面更正了这个判断。

**代价**：一次错误的对外结论 + 一份差点发出去的返修单。**正确做法是等 agent 结束（或至少
等它的 report 文件出现）再验，且验的是整节而不是关键词。**

## L24 开市前竞价的「现价」不是成交价，据它建因果链会污染全部并行 subagent

港股 09:00–09:20、A 股 09:15–09:25 是集合竞价时段，撮合完成前腾讯 `qt.gtimg.cn` 返回的"现价"是
**挂单参考价**，成交量极小甚至为 0，与真实开盘价可差 15%。**取数时必须同时看时戳与成交量**：
时戳在开盘前 + 成交量为 0 或极小 = 竞价参考价，**不可用作行情锚，更不可据以建立因果链**。

**机制**：可机械化（A1 取数脚本可加断言：时戳早于开盘时刻 或 成交量 < 阈值 → 拒绝返回该价）

**案例**：

2026-08-25 建滔积层板轮。控制者 **09:00:20** 取 `hk01888` 得 **40.360 / 前收 35.100 / +14.99%、成交量 95 手**，
据此判定「26H1 中报大超预期导致股价跳涨、较旧档锚 +38.5%」，并把这条因果**写进三路 A 的派发 prompt 作为核心触发**。

实际 09:20 开盘后为 **35.320（+0.63%）** —— 40.360 是竞价参考价。真实区间涨幅是 +20.7% 而非 +38.5%，
且**中报当日（08-24）实际收跌 −5.85%**，区间顶 42.12 出现在中报之前的 08-17：**因果完全反了，中报是负面股价事件。**

A2 最先发现并反向纠正控制者。控制者随后两轮 `SendMessage` 校准 A1/A3，但两路都已据错误前提写了成段内容
（A3 已写出「+14.99% 的真正驱动是七月 11 亿这句新信息」整段因果分析），须返工重写。

**代价**：三路 subagent 全部被污染 + 两轮校准 + A3 的 evidence/report 各改到 v3。
**根因是控制者在派发前没验证自己的前置观察**——[L5] 要求把控制者前置观察写成「我的推断是 X，请核实 X 是否成立」，
本轮控制者确实这么写了，**这个格式救了场**（三路都在核实中发现问题），但**行情数字这类可以自验的事实，应该在派发前就自验，
而不是靠格式兜底**。

## L25 给财报设阈值判据前，必须用同期历史回测确认该指标对该公司有判别力

半年 vs 全年、单季 vs 年度的阈值判据尤其危险：季节性与营运资金周期会让一个指标在特定期间**天然落在阈值一侧**，
此时该阈值不是在测量经营变化，而是在测量日历。**回测成本极低（同一套算法跑一遍上年同期），
不做的代价是整条论证链建立在伪指标上。**

**机制**：仅措辞（写 §11 监控指标时的纪律）

**案例**：

2026-08-25 建滔积层板轮。旧档（07-30）把「**26H1 净现比 ≥1.0x → 本档最强看空证据被推翻 / <0.8x → 恶化确认**」
设为"**唯一能在中报单独裁决的指标**"，并写进 §11 与重新承做的买点条件。

中报落地后 A1 推算 26H1 净现比 **~0.25x**，控制者据旧档判据下裁定「旧档最强看空证据不但未被推翻，反而大幅强化」，
并写进给 Phase B 写手的派发。

**A1 随后用同一套方法回测 25H1：OCF ≈ −3.9 亿，也是负的**；FY25 全年 OCF 21.60 亿几乎全部产生于 H2。
→ **这家公司 H1 天然吸现金、H2 释放。旧档是拿一个季节性吸现金的半年去比全年口径，属口径错配，判据本身不成立。**
改用真同比后结论反转：营运资金增量÷净利 25H1 1.84x → 26H1 **1.13x（改善）**、周转天数 126→126 日**持平**、
存货/应收/票据 yoy 全部**未触发** 15pp 阈值。

控制者据此发终局修订推翻自己的裁定，写手已落盘的段落需回改，措辞从"崩塌/现金质量恶化"降级为
"扩张期 FCF 为负、靠净负债支撑"。

**推论（写档时执行）**：§11 里凡"半年/单季阈值"，都应**同时标注该阈值的同期历史值作为基准**
（例：「26H1 净现比 <0.8x = 恶化（对照：25H1 为 X、24H1 为 Y）」），否则后续重做无法判断触发是否有意义。
**A1 派发时应固定加一句**：「凡你用来裁决的比率型指标，先跑一遍上年同期，确认该指标在本公司不存在季节性偏置。」

## L26 要求 subagent 达成某条规格前，先跑一次全仓统计确认该规格的实际执行状况

规格文件写的是**应然**，存量档是**实然**。两者偏离时，孤立地要求本轮达标既不公平，也会逼 subagent
用损害质量的方式凑数。**发现偏离应报给用户决定（改规格 or 统一整改），不该让本轮档独自承担。**

**机制**：仅措辞

**案例**：

2026-08-25 建滔积层板轮。控制者据 `buffett-doc-spec`「index.md ≤12KB」**两次**要求写手压缩
（22,008 → 16,023 bytes，仍要求继续压）。写手第三次顶回来并给出证据：存量文件夹档实际为 15.0–18.7KB，
且明说「要再降 4KB，**只能删数字或删 §11 的硬阈值表，两者都违反指令**」。

控制者亲验全仓 6 份文件夹档 index.md：**14,033 / 14,885 / 15,891 / 16,167 / 16,747 / 18,551 —— 全部超标，无一例外。**
该规格从未被执行。控制者撤回指令，并把"改规格还是统一压缩存量档"报给用户裁决。

**代价**：两轮无效返修，且写手一度处在"为达标而删数字"的边缘。
**subagent 拿证据顶回控制者的指令时，先亲验它的证据，别默认自己的指令正确**——本轮写手是对的。
