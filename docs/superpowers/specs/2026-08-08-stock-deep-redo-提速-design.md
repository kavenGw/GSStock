# stock-deep-redo 提速设计（2026-08-08）

## 背景与实测基线

2026-08-08 完整跑了一遍零跑汽车（09863.HK）的深度重做，按 subagent 消息时间戳实测各阶段墙钟：

| 阶段 | 模型 | 墙钟 | 备注 |
|---|---|---|---|
| Phase A 采证 | opus | ~7 min | 单 agent 顺序跑六大块 |
| Phase B 撰写 | opus | ~15.5 min | 产出 888 行，最大头 |
| 合并审查 | sonnet | ~5.5 min | |
| Phase C 收尾 | sonnet | ~4 min | |
| 控制者开销 | — | ~5 min+ | 含 3 次 SendMessage 追要报告 + 自行复核 |
| **合计** | | **~40 min** | |

参考数据：全仓 231 份 buffett 档行数 median 300 / p75 419 / max 1531；2026-08 这批普遍 600–890 行。

## 目标与取舍（已与用户确认）

- **优化目标：墙钟时间**（用户在干等），不是 token 成本、不是打断次数、不是产出长度。
- **深度不降**：不给正文加篇幅上限。Phase B 保持单一 opus 写手，不拆分——888 行长文的价值很大程度在「§6 论点 → §9 估值 → §10 评级」的链式推导，拆开写最容易断链。
- **接受 token 成本上升**作为墙钟收益的代价（见杠杆二）。
- **目标值：40 min → ~29 min。**

## 范围

**仅改 `.claude/skills/stock-deep-redo/`**（SKILL.md + references/playbook.md），加一条可选的 `.claude/rules/` 沉淀。不碰 `app/` 代码，不需要 worktree（投研 skill 改动按分支策略在 main 直接进行）。

### 范围收敛记录（重要）

初始设想是「三个写档 skill 同步改」，经核查该前提不成立：

- **`analyze-category` 不存在**——CLAUDE.md 的投研 skill 路由列了它，但 `.claude/skills/` 下无此目录。这是一条悬空引用，属独立问题，**不并入本次**。
- **`news-impact` 零 subagent**——它是单上下文 6 步流程（核实新闻 → 池索引匹配 → 逐标的判传导 → 落 theme 档 → 对称 lint → 汇报），本设计要治的「idle 往返」「采证串行」两个毛病它压根没有。

因此三根杠杆里有两根在别处无处可施，范围自然收敛回单一 skill。

### 明确排除

- `.claude/skills/stock-deep-redo-workspace/`（skill-creator 跑崩的残留：`optim.log` 内容为 `ModuleNotFoundError: No module named 'anthropic'`）——独立清理项。
- CLAUDE.md 对 `analyze-category` 的悬空引用——独立问题。

## 杠杆一：汇报写文件，消除 idle 往返

### 问题

本轮 4 个 subagent 中有 3 个（采证 / 撰写 / 审查）完成后**只发 idle 通知、不回传正文**，控制者必须逐个 `SendMessage` 追要，每次一个完整往返。审查 agent 的 prompt 里已明写「最终回复必须包含完整的两段审查正文，不要只回 idle」，**它仍然先回 idle**——证明靠 prompt 措辞加压无效，必须改机制。

### 方案

每个 Phase 的派发 prompt 末尾加统一硬约定：

> 汇报**必须**用 Write 写到 `.omc/artifacts/<股票名>-<日期>-<阶段标识>-report.md`，写完才结束。消息回传是可选冗余通道。

阶段标识固定六种（含审查——审查也是必须追要报告的重灾区之一）：`phaseA1` / `phaseA2` / `phaseA3` / `phaseB` / `review` / `phaseC`。

控制者不再等消息，直接 `Read` 该文件。

### 收益与代价

- **收益 ~5 min**，且顺带加固一条既有教训：subagent 的口头汇报本就不可信（曾自报「一次性脚本已删」而实际未删），落成文件后控制者的亲验对象从「它说了什么」变成「它写了什么 + 我自己查到什么」。
- **代价近零**：多写一个文件，`.omc/artifacts/` 已 gitignore。

## 杠杆二：Phase A 拆三路并行采证

### 问题

Phase A 单 agent 顺序跑六大块（行情锚 / 最新财报 / 核心论点逐条 / AI 维度 / 成长扩产 / 可比公司），六块之间无依赖，纯串行浪费。

### 方案

三个 opus 并行，各写各的 evidence 片段，**不加合并 agent**（合并会把省下的时间串回去）：

| Agent | 负责 | 产出 |
|---|---|---|
| **A1 数据锚** | 实时行情（腾讯 + stockanalysis 双源 + 市值=现价×总股本自洽校验）、最新财报 / 逐月交付、可比公司估值表 | `<股票名>-<日期>-evidence-A1-数据锚.md` |
| **A2 论点验证** | 核心多空论点逐条联网核实（最重的一块） | `<股票名>-<日期>-evidence-A2-论点.md` |
| **A3 lens 专项** | 命中的横切 / 板块 lens 必查清单（AI 维度、成长扩产、需求兑证） | `<股票名>-<日期>-evidence-A3-lens.md` |

Phase B 同时读三份。

### 两个风险与处置

1. **数字打架**（A1 算出市值 X，A2 在论点里引了另一口径）。
   处置：prompt 硬性规定 **A1 是所有行情 / 财务硬数字的唯一权威源**；A2/A3 涉及数字时以定性表述为主，冲突一律以 A1 为准；要求 Phase B 发现冲突时在正文显式标注。
2. **「相对旧档变化清单」没人写**——本轮那张 30 条对照表是全档最有价值的产物之一，但需要全局视野，任何单个并行 agent 都写不了。
   处置：**移交 Phase B**。它本来就要读全部三份 evidence + 旧档，天然有全局视野，不增加串行时间。

### 收益与代价

- **收益 7 min → ~4 min**（由最慢的 A2 决定）。
- **代价：token 成本明显上升**——3 个 opus 并行，且边界重叠处有少量重复检索。这是墙钟优先取舍下被接受的代价，不隐瞒。

## 杠杆三：收紧 Phase B 注入包

### 问题

本轮写手自读 6 份材料，其中两份是浪费：

| 材料 | 判断 |
|---|---|
| evidence.md（43.9K） | 必读，事实源 |
| 旧档 | 必读，翻转对照 |
| playbook.md（234 行） | 必读，规格 |
| `Skill buffett` 框架 | 必读，skill 设计如此 |
| **兄弟档（791 行）** | **浪费**——让它读全文只为「参考质量水位与口径」，实际有用的仅三五条（如小鹏用 TTM 营收作分母、bull 封顶 20%、买点取 30% 折价） |
| **sector-lenses.md（261 行）** | **浪费**——命中的只有 AI + 成长两节约 70 行 |

sector-lenses 这条尤其值得记：SKILL.md 本已写明「控制者把命中节的【必查清单】【撰写落点】**摘出**，分别注入 Phase A / Phase B 提示」，本轮控制者只报了 lens 名字让 subagent 自己去读，**是没执行既有约定**。

### 方案

- 控制者把兄弟档口径提炼成 3–5 行塞进 prompt，**不让写手读兄弟档全文**。
- 控制者把命中 lens 的【撰写落点】【双面必答】【监控指标模板】**直接内联**进 prompt，**不让写手读 sector-lenses.md**。
- 收紧 SKILL.md / playbook.md 措辞为强制内联，**不留「指路」这个选项**（当前措辞允许控制者偷懒）。

### 收益与代价

**收益 ~2–3 min**，三根杠杆里最小的一根，但代价为零。

## 附加：耗时度量

否则「提速了」不可证伪。做法很轻：每个 phase 的汇报文件头两行记 `start` / `end` 时间戳（subagent 跑一次 `date` 即可），控制者收尾时汇总成一行耗时账。

跑两三只股即可拿到真实基线，并验证杠杆二实际省了几分钟、token 涨了多少。

## 验收标准

1. `.claude/skills/stock-deep-redo/SKILL.md` 与 `references/playbook.md` 改动落地，措辞不再允许「让 subagent 自己去读 lens 文件」。
2. 下一只股实跑一遍，四个 phase 的汇报文件均在 `.omc/artifacts/` 落盘，控制者**零次** `SendMessage` 追要报告。
3. Phase A 三路并行产出三份 evidence 片段，Phase B 正文中的行情 / 财务硬数字与 A1 片段一致。
4. 收尾汇报含一行耗时账，总墙钟 < 35 min（首次实跑允许留缓冲，目标 ~29 min）。
5. 产出档的深度不低于当前水位（节数齐全、审查仍给 SPEC-COMPLIANT + APPROVED）。

## 不做的事（YAGNI）

- 不给正文加篇幅上限
- 不拆 Phase B 为多写手
- 不做「写手提前开工」的流水线重叠（旧档过时事实会被写进去洗不掉——本轮旧档就有汇率 0.92、PB 5.13、现金 378 亿三处错值）
- 不让审查与 Phase C 重叠（C 要提交，风险高于 ~3 min 收益）
- 不降 Phase B 的模型档位
