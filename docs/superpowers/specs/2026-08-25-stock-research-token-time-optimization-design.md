# stock-research 优化设计 —— 消除重复支付与返工

> 日期：2026-08-25 ｜ 状态：待实现
> 基线数据来自 2026-08-25 建滔积层板 1888.HK 全量重做（模式 1）的实测。

## 1. 问题

用户诉求两条：**token 消耗大**、**用时很长**。实测数据如下，其中两项与直觉不符。

### 1.1 体量分布

| 位置 | 体量 | 备注 |
|---|---|---|
| `references/` 全部 | 156KB | 其中 `lessons.md` 62KB / 708 行 = 39% |
| 单轮 subagent 产出 | 292KB | evidence 三份 155KB + report 三份 56KB |
| 单轮派发 prompt | 约 24KB | 四份（A1/A2/A3/B），**其中约 15KB 是每轮重写的固定内容** |
| 最终七文件 | 173KB | |

### 1.2 时间分布

| 段 | 耗时 | 占比 |
|---|---|---|
| Phase A 三路并行（取最慢） | 29min | 23% |
| Phase B 单路撰写 | 51min | 41% |
| 审查 + 复核 | 约 20min | 16% |
| Phase C 收尾 | 约 10min | 8% |
| 控制者接棒修 3 Major + 5 Nit | 约 15min | 12% |

**其中约 40min 是返工**：控制者竞价假价污染三路后的两轮校准（L24）、A1 自我推翻净现比判据后写手的回改（L25）、审查后的 Major 修复。返工里至少一半可机械预防。

### 1.3 两项与直觉不符的发现

1. **`lessons.md` 62KB 不是消耗源。** 它设计上是「按 `[Ln]` 编号翻、不通读」，实测本轮控制者全程只 `grep` 标题行，未读正文。拆它收益低，**本设计不动它**。
2. **report 是 evidence 的摘要重述。** 实测行级重叠率 72.7%–83.0%、数字覆盖率 89.2%–97.7%。三份 report 合计约 30K 字，**其中八成是重复生成的内容**。

## 2. 已确认的约束（用户决策）

| # | 决策 | 含义 |
|---|---|---|
| D1 | **质量不降，只榨纯浪费** | 不砍采证路数、不砍审查轮次、不限 evidence 篇幅 |
| D2 | **内联铁律改为混合** | 静态可预拆的（lens）改 subagent 自读；动态每轮不同的（兄弟档口径、控制者裁定）仍由控制者摘写内联 |
| D3 | **时间优先攻「把教训机械化防返工」** | 不做流程重叠，不拆 Phase B |
| D4 | **合并 evidence 与 report** | 单文件承载明细层 + 结论层 |

## 3. 设计

### 3.1 agent 定义层（`.claude/agents/sr-*.md`）

新建六份定义，把每轮重写的固定内容一次性固化。frontmatter 字段 `model` / `effort` / `skills` / `tools` 均经验证真实生效（全局 140 份插件 agent 定义中 `model` 用 111 次、`effort` 用 7 次、`skills` 用 2 次）。

| agent | model | effort | skills | 固化内容 |
|---|---|---|---|---|
| `sr-a1-anchor` | opus | high | — | 证据分级三档；取数脚本与港股字段身份表（`[57]`=PE-TTM、`[58]`=PB、`[39]`=静态 PE）；**比率型指标必须回测上年同期**（L25）；市值自洽校验；行情锚时点铁律；汇报协议 |
| `sr-a2-thesis` | opus | medium | — | 多空论点核实规矩；每条必给反驳点；供给侧论点拆解法；机构分歧标注 |
| `sr-a3-lens` | opus | medium | — | **lens 选取规则与文件映射表**（见 3.2）；【真敏感/蹭概念】判定；【实证/概念】标注 |
| `sr-writer` | opus | high | `buffett`, `buffett-doc-spec` | 七文件结构；抗中断落盘顺序；数字镜像纪律；变化清单格式 |
| `sr-reviewer` | sonnet | high | `buffett-doc-spec` | 审查输出格式；8 条红线；两段正文必须写文件 |
| `sr-finalize` | sonnet | **low** | — | `finalize.md` 全文；提交铁律 |

派发时只剩变量：标的 + 代码 + 日期 + 控制者裁定 + 兄弟档摘要 + 本轮特有必查项。

**命名与防误触发**：统一 `sr-` 前缀；`description` 写死「仅由 stock-research 控制者派发，勿直接调用」。这是约定不是强制，属已知残余风险。

### 3.2 lens 拆分

`references/sector-lenses.md`（261 行）现含 **7 个 lens，其中 3 个是横切**（对每只股默认跑识别）、4 个是板块专属。拆分后命名以 `x-` 前缀区分两类：

| 文件 | 类型 | 原节 |
|---|---|---|
| `lenses/x-ai.md` | 横切（默认） | AI |
| `lenses/x-growth.md` | 横切（默认） | 成长 / 扩产 / 客户增长 |
| `lenses/x-dividend-value.md` | 横切（consumer/materials/energy/industrial/financial 默认） | 分红 / 价值股 |
| `lenses/pcb-ccl.md` | 板块专属 | PCB / CCL |
| `lenses/storage-dram-nand.md` | 板块专属 | 存储 — DRAM / NAND |
| `lenses/storage-nor-flash.md` | 板块专属 | 存储 — NOR Flash |
| `lenses/metals-copper.md` | 板块专属 | 铜 / 铜矿 / 有色金属 |

每份保留完整四节（【必查清单】【撰写落点】【双面必答】【监控指标模板】）。

**选取规则**（写进 `sr-a3-lens` 定义，含上表映射，省一次索引读取）：加载全部 `x-*.md` + 按 subsector/主营匹配的 1–2 份板块专属；无匹配板块专属时只跑横切并明写「无板块专属 lens 命中」。

拆分**推翻了内联铁律的前提**：原铁律理由是「subagent 自读会挑错节——sector-lenses 261 行只命中约 70 行」，拆分后文件本身即精确粒度，挑错节不再可能。

**注意【撰写落点】的去向**：该节是给 Phase B 写手的，不是给 A3 的。拆分后由 `sr-writer` 按同一映射表自读命中 lens 的该节，控制者不再摘写内联——这是 D2「静态改自读」在写手侧的同等应用。

### 3.3 产出契约：evidence + report 合并

`<股票名>-<日期>-<lane>.md` 单文件：

```
start: YYYY-MM-DD HH:MM:SS

## 明细层        ← 采证过程中边采边追加
## 结论层        ← 全部完成后最后写（其存在即完成信号）

end: YYYY-MM-DD HH:MM:SS
```

控制者 `tail` 取结论层，需要时 `grep`/`sed` 下钻明细层。

### 3.4 闸门：从猜测改为确定性判定

现有 lane 检查含 `--quiet-min 3`（mtime 静默 3 分钟才算收工），是在**猜** subagent 是否收工。本轮为此空等三次。

`deep_redo_gate.py` 已有 `END_STAMP_RE = re.compile(r'^end:\s*\S', re.M)`，合并后判据直接改为「文件含 `end:` 戳」——subagent 显式写下的完成声明，比 mtime 猜测可靠。**废除 `--quiet-min`**，每轮省数分钟空等，并消除「静默 3 分钟但其实卡住」的误判。

保留 `--stale-min`，语义改为：**明细层有内容但无 `end:` 戳超过 N 分钟 → 大概率死在交付前**（对应 L22）。

### 3.5 `scripts/quote_guard.py` —— 把 L24 变成代码

```
输入：代码（hk01888 / sh600183 / NVDA）
断言：① 时戳落在该市场连续交易时段内
        （港股 09:30–12:00 / 13:00–16:00；A 股 09:30–11:30 / 13:00–15:00；美股按 ET）
      ② 成交量 > 0 且高于阈值
      ③ 市值自洽：现价 × 总股本 ≈ 市值字段
任一不满足 → 拒绝返回价格，报错说明是竞价参考价 / 停牌 / 字段错位
--allow-preopen 显式覆盖，输出强制标注「竞价参考价，不可作行情锚」
```

`sr-a1-anchor` 定义中写死：取行情必须经 `quote_guard.py`，不得直接解析腾讯字段。

## 4. 迁移

分三批，按「能否独立生效」切。**在独立 git worktree 中进行**（`dev-environment.md` 分支策略：改 skill 属「其他功能」；且本仓存在并行 session，在 main 改到一半会让正在跑投研的 session 读到半成品契约）。

| 批 | 内容 | 性质 |
|---|---|---|
| **1** | 6 份 agent 定义 + `quote_guard.py` + 单测 | **纯加法**。旧派发方式并存，随时可删文件回退。合并后立刻拿到 model/effort 收益 |
| **2** | lens 拆分 + 删 `sector-lenses.md` + 同步 **4 处引用**（`SKILL.md:59` references 索引表、`dispatch.md:29-30` 内联铁律、`mode-deep.md:10` 配套文件说明、`mode-deep.md:47` 先做步骤 5「选 lens」） | **原子**。任一处漏改，控制者就会去读已删文件 |
| **3** | evidence/report 合并契约 + `deep_redo_gate.py` + 四份 `mode-*.md` 同步 | **原子，最危险**。契约、闸门、流程文档任一不同步则闸门找不到文件 |

回退粒度 = 批。

## 5. 验证

| 层 | 验什么 | 方式 |
|---|---|---|
| agent 定义 | 6 个可识别、model/effort 生效 | `ListAgents` 列出 `sr-*`；派空任务观察 |
| lens 拆分 | **内容无损** | 拆分前后正文字节数守恒（允许 frontmatter 差异）；每份含完整四节 |
| `quote_guard` | 三类坏输入被拒 | 单测：竞价时戳 / 成交量为 0 / 市值不自洽 → 各断言拒绝；正常盘中价放行 |
| 闸门 | 新格式判定正确 | 构造假文件：含 `end:` → exit 0；不含 → exit 1；明细层有内容且无 `end:` 超 `--stale-min` → 报疑似死在交付前 |
| 端到端 | token / 时间是否真降 | 下一轮真实投研跑一次，对基线（artifacts 292KB、prompt 约 24KB、总时长约 2h05）对比 |

端到端仅用于校准预期，**不作为批 1/2/3 的合并前置**——它只能事后验证且单样本噪声大（本轮即被写手配额中断干扰）。

## 6. 明确不做（YAGNI）

| 不做 | 理由 |
|---|---|
| 拆 `lessons.md` | 实测不通读，按编号翻；拆分收益低于改动成本 |
| 限 evidence 篇幅 | 违反 D1。本轮 A1 evidence 中的净现比双路径推算全过程正是质量来源 |
| 拆 Phase B 写手 | 与 skill 明文冲突（「拆写手断论点→估值→评级链」） |
| 审查与 Phase C 重叠 | D3 未选；且审查报 Critical 时需回退 |
| 用 Workflow 脚本编排 | 投研流程需控制者中途做判断（本轮 18 条裁定），不适合确定性脚本 |

## 7. 待验假设与残余风险

| # | 假设 / 风险 | 处置 |
|---|---|---|
| A1 | **省下的 token 量是估算。** 固定内容约 15KB/轮 + lens 内联约 4KB/轮系本轮 prompt 实测，但 agent 定义 body 本身仍进 subagent 上下文——净收益来自「不重复传输」而非「不存在」，实际降幅可能低于直觉 | 端到端实测校准 |
| A2 | **`effort` 各档位的实际行为差异无实测数据。** 该字段全局仅 7 处使用（对比 `model` 111 处） | 批 1 合并后观察 `sr-finalize`（low）是否仍能正确完成收尾 |
| A3 | agent 定义出现在全局列表，可能被其他任务误触发 | `sr-` 前缀 + description 声明；属约定非强制 |
| A4 | 合并单文件后，subagent 若在写结论层时崩溃，明细层已落盘但无 `end:` 戳 | `--stale-min` 区分「还在跑」与「死在交付前」（L22） |
