## §3 · 逐标的传导分析（仅中量级以上展开 → 只有东阳光）

### 3.1 接旧 thesis：这条新闻是它建档结论的**又一个实例**，不是反例

东阳光 buffett 档（`2026-07-12`，**watch**，就在本公告的同一个周末落笔）的核心判断是：

> 「秦淮数据是真资产、310 亿是真合同——这一点必须先承认。但**真资产不等于好价格**。」
> 「base 情景：**310 亿长单的增量按"需追加 capex 与负债才能承接"处理，不给额外溢价**。」

**本次第三笔单完全落在这句话的射程之内。**旧档的估值三档（bear 3.16 / base 8.96 / bull 13.03，期望内在价值 **8.03 元**）**不因这笔单而改变**，理由见 §3.2 的算术。

**需要更新的是事实，不是结论**：长单口径从「两笔 310 亿」→「**三笔 390–460 亿**」；风险清单新增一条「**合同条款单向不对称**」（建档时未掌握）。

### 3.2 把金额拆开：这不是"锁定 460 亿现金流"，是"先借 200 亿才能开始收钱"

> 以下为**本档自算**，多处使用行业经验假设，逐条标注，**不作为精确值，只作为量级判断**。

**(a) 单笔（130–150 亿）的资本需求**

| 步骤 | 测算 | 说明 |
|---|---|---|
| 含税合同额 | 130–150 亿 | 【硬-公告】 |
| 不含税（算力服务按 6% 增值税） | ≈ **123–142 亿** | 【自算】 |
| 年均不含税收入（5 年） | ≈ **24.5–28.3 亿** | 【自算】 |
| **前期服务器采购 capex** | ≈ **65–90 亿**（一次性，部署完才开始按月收费） | 【**假设**：GPU 算力租赁合同中硬件成本通常占合同额 **50–60%**，为行业经验值，**无第三方来源**】 |
| 自下而上交叉校验 | 年租 24.5–28.3 亿 ÷ 单台 8 卡 GPU 服务器年租 ~100–150 万 → **约 1,600–2,800 台** × 单台采购 200–300 万 → **32–84 亿** | 两条口径区间重叠 → 取 **65–90 亿**量级 |
| 反推 IT 容量需求 | 1,600–2,800 台 × ~10kW ≈ **20–30MW** | 用于 §2 中科华数据的配套需求量级 |

**(b) 三笔合计（390–460 亿）的资本需求 —— 本档最锋利的一个数字**

| 项 | 数值 |
|---|---|
| 三笔合同含税总额 | **390–460 亿** |
| **对应前期服务器采购总 capex（按 50–60%）** | **≈ 195–275 亿元**【自算·假设】 |
| 对照：东阳光 **26Q1 末有息债务余额** | **161.14 亿元**【硬】 |
| 对照：26Q1 末负债合计 / 资产负债率 | **220.40 亿 / 67%**【硬】；**并表秦淮数据后 72.39%**【硬-重组草案】 |
| 对照：流动比率 / 速动比率 | **0.89 / 0.69**【硬】 |
| 对照：2025 财务费用 | **5.32 亿**【硬】 |

> **要承接这三笔单，东阳光需要投入的前期硬件资金（约 195–275 亿），超过它当前全部有息债务（161 亿）。** 而它已经背着 67%（并表后 72.4%）的负债率、0.69 的速动比率、和一笔 280 亿的秦淮数据并购贷款。
>
> **市场的读法**：签了 460 亿大单 → 现金流锁定 → 股价涨停。
> **算术的读法**：先融 200 亿+ 买服务器 → 财务费用暴增 → **验收权还在匿名客户手里，对方毁约无需担责** → 然后才轮到"按月收钱"。

**(c) 容量不是瓶颈，资金才是（诚实地给多头记一分）**

秦淮数据 **782MW 在运（上架率 >90%，余量约 78MW）+ 137MW 在建**。三笔单反推所需 IT 容量约 **60–90MW** → **现有余量 + 在建足以承接**。这一点上多头是对的：**这不是画饼，物理机房是真的在那里**。瓶颈不在机房，**在买服务器的钱**。

### 3.3 双面看：多头一侧必须讲到最强

**多头（真实、不稀释）**：
1. 合同是**公告级**的，不是意向；公司称前期已签合同"均已严格按照合同约定及时交付"。
2. 秦淮数据的物理容量真实可承接（§3.2c），**不需要新建机房**，边际投入只有服务器。
3. 三笔累计年均 78–92 亿收入 = 2025 全年营收的 **52–62%**——**如果全额兑现，这确实会把东阳光变成另一家公司**。
4. 按月结算 + 5 年期，现金流形态优于一次性设备销售。

**空头（同样真实）**：
1. **验收条款单向不对称**——性能/部署/稳定性/硬件合规任一不达标，客户可**无责解约**，东阳光独吞前期投入损失。这把"合同金额"从**承诺**降格为**期权**（对方持有的期权）。
2. **客户三笔全匿名**。年均 78–92 亿收入却不知道对手方是谁 → 无法评估违约、集中度、续约、也无法用其 capex guidance 交叉验证。
3. **资金缺口 195–275 亿 > 现有有息债务 161 亿**（§3.2b）。公司自己在公告里承认"资金筹措未到位可能导致违约"。
4. **单笔经济性可能远不如金额性感**：粗算 5 年不含税收入 123–142 亿 − 服务器 65–90 亿 − 电费（20–30MW × 5 年 ≈ 4–7 亿）− 运维 ≈ **5 年净现金 25–65 亿**，再扣 65–90 亿垫资的 5 年融资成本（按 ~4% 计约 13–18 亿）→ **净利润薄，且全部风险敞口（技术迭代、GPU 残值、客户违约）由东阳光独担**。【自算·多重假设，仅为量级】
5. **模式本身的红旗**：两个月三笔、金额一笔比一笔大、客户一个比一个匿名（A→B→C）、股价 18 个月 +229%、控股股东质押 81–87%。**这个组合需要的不是兴奋，是警惕。**

### 3.4 评级结论

| 项 | 判定 |
|---|---|
| 评级变动 | **维持 watch，不变** |
| 估值变动 | **不变**（bear 3.16 / base 8.96 / bull 13.03，期望内在价值 **8.03 元**） |
| 安全边际 | **仍为 −78.4%**（现价 37.15 元）——**若周一因本消息上冲，缺口只会更大** |
| bull 概率 | **不上调**（仍 20%）。理由：bull 的门控卡在「客户 capex 能见度」，第三笔单**没有解决这个黑洞，反而把它扩大了一倍**（从两个匿名客户变成三个） |
| 新增风险条目 | **合同条款单向不对称**（验收不通过客户可无责解约）——建档时未掌握，本档补入 |

**为什么增量 130–150 亿的合同不抬高一分钱估值**：因为旧档的 base 情景**早已写明**「长单增量按需追加 capex 与负债承接、不给额外溢价」。第三笔单带来的是**等量的收入与等量的债务**，股权价值增量在扣除融资成本与违约风险折价后**趋近于零**。**给一笔需要先借 200 亿才能履行、且对方可以无责毁约的合同加估值溢价，是把负债当资产。**

## §4 · 操作含义

1. **东阳光（600673，watch）**：**维持 watch，不买**。本次事件**不改变**任何估值参数。**若 07-13 因消息面涨停/大涨，是安全边际进一步恶化，不是机会**。旧档 §11.2 的监控阈值全部继续有效，并新增一条：**关注三笔长单是否出现"验收不通过/订单解除"公告**——按合同条款，这类事件对客户零成本、对东阳光是全额损失。
2. **算力硬件链（浪潮/工业富联/联想/海光）**：**不因本事件调整任何评级**。传导量级低（65–90 亿采购、供应商未指名、分摊多年），把这条新闻当"服务器订单利好"买入上游，是**在给一个还没确定供应商的采购计划付钱**。
3. **算力租赁同业（优刻得/金山云）**：**不因本事件调整评级**。行业景气验证与新增供给竞争互相抵消。
4. **无影响标的（制冷剂链、被动元件、服务器 BOM 二三阶）**：**明确无基本面传导**。若这些标的在 07-13 因"东阳光算力大单"出现同涨，属**情绪联动**，不构成买入理由。
5. **给这类"匿名客户巨额长单"事件的一般性判断框架（本档沉淀）**：
   - 先问**谁垫资**——垫资方是风险承担方，不是受益方；
   - 再问**验收权在谁手里**——验收权在对方且对方毁约无责，合同金额就只是对方的期权；
   - 再问**钱从哪来**——所需 capex 与现有有息债务、速动比率的比值，比合同金额本身更能预测结局；
   - 最后才问**客户是谁**——如果这一条答不上来，前三条的答案再好也要打折。
